# TgAuth — авторизация Minecraft через Telegram

Паролей нет вообще. Личность игрока подтверждается привязанным аккаунтом Telegram.

## Как это работает

**Первый вход.** Игрока замораживает (не ходит, не пишет, не бьёт, неуязвим).
В чате и на экране появляется код вида `K7F2QX`. Игрок отправляет его боту —
аккаунт привязан, заморозка снята.

**Обычный вход.** Если IP тот же, что в прошлый раз, и заходил не позже чем
`trusted-days` назад — пускает молча, игрок даже не заметит проверки.

**Вход с нового IP.** Бот присылает сообщение «Вход в игру, ник X, IP Y» с
кнопками «Это я» / «Не я». Нажал — играет. Отклонил — выкидывает. Не ответил
за минуту — тоже выкидывает.

Пароля не существует, значит его нельзя подобрать, слить или забыть.

---

## Два режима работы

В `config.yml` есть переключатель `telegram.mode`:

### `polling` — по умолчанию, рекомендуется

Плагин **сам** общается с Telegram. Внешний бот и открытые порты не нужны,
достаточно исходящего интернета, который есть везде.

Подходит для **хостингов майнкрафта с панелью**, где нельзя открыть свой порт.

Настройка сводится к одной строке — вписать `bot-token`. Всё, папку `bot/`
можно не трогать.

### `api` — если бот нужен отдельно

Плагин поднимает HTTP-сервер, к нему стучится бот из папки `bot/`.
Нужно, только если вы хотите совместить авторизацию с уже существующим ботом
или держать логику отдельно.

Тогда порт `8787` должен быть доступен боту, а токены в двух конфигах —
совпадать.

**Важно:** один токен Telegram нельзя опрашивать двумя программами сразу.
Если запустить и `polling`, и внешнего бота на одном токене, Telegram будет
отвечать ошибкой 409. Либо один режим, либо два разных бота.

## Сборка плагина

Нужна Java 17+ и Maven.

```bash
cd plugin
mvn clean package
```

Готовый файл: `plugin/target/TgAuth.jar` → кинуть в папку `plugins/` сервера.

Плагин под Paper/Spigot 1.20+. Внешних библиотек нет: HTTP-сервер из JDK,
Gson уже внутри сервера.

## Настройка

### 1. Бот в Telegram

Напишите [@BotFather](https://t.me/BotFather) → `/newbot` → получите токен.

### 2. Плагин

Запустите сервер один раз, чтобы создался `plugins/TgAuth/config.yml`, затем:

```yaml
telegram:
  bot-token: "123456:AA..."      # токен от BotFather
  bot-username: "MyServerAuthBot" # юзернейм бота без @
  server-name: "Мой сервер"

api:
  token: "длинная-случайная-строка"   # придумайте сами
```

Сгенерировать токен можно так:

```bash
openssl rand -hex 32
```

### 3. Бот

```bash
cd bot
pip install -r requirements.txt
cp config.example.json config.json
```

В `config.json` впишите тот же `bot_token` и **тот же самый** `api_token`,
что в `config.yml` плагина. Если они не совпадут, плагин будет отвечать 403.

```bash
python bot.py
```

### 4. Проверка

Перезапустите сервер, зайдите в игру. Должен появиться код — отправьте его боту.

## Где что должно стоять

Бот и сервер по умолчанию **на одной машине**: плагин слушает `127.0.0.1:8787`,
наружу порт не торчит.

Если бот на другой машине — поменяйте `api.bind` на `0.0.0.0` и **обязательно**
закройте порт фаерволом, оставив доступ только с IP бота:

```bash
ufw allow from <IP_бота> to any port 8787
```

Иначе кто угодно сможет дёргать API и логиниться за чужих игроков.

## Команды

**Игрокам (в боте):**
- `/start` — инструкция
- `/status` — состояние привязки
- `/unlink` — отвязать аккаунт

**Админам (в игре):** нужно право `tgauth.admin`
- `/tgauth reload` — перечитать конфиг и базу
- `/tgauth info <ник>` — кто привязан к аккаунту
- `/tgauth unlink <ник>` — снять привязку
- `/tgauth force <ник>` — пустить игрока вручную, если бот лежит

Последняя команда важна: если Telegram недоступен, а игроку срочно нужно
попасть в игру, админ пускает его руками.

## Настройки авторизации

```yaml
auth:
  code-lifetime-seconds: 300   # сколько живёт код регистрации
  confirm-timeout-seconds: 60  # сколько ждём нажатия кнопки
  trusted-days: 7              # сколько дней IP считается доверенным
  code-length: 6
  blindness: true              # слепота до входа
```

`trusted-days: 0` заставит подтверждать **каждый** вход — строго, но игроков
раздражает. `30` — мягко, но при смене IP всё равно спросит.

Все тексты игроку лежат в секции `messages` и меняются без пересборки.

## Известные ограничения

- **Динамический IP.** У мобильных операторов IP скачет, такие игроки будут
  подтверждать вход часто. Лечится увеличением `trusted-days` — привязка всё
  равно держится на Telegram, а не на IP.
- **Данные в YAML.** Для сервера на сотни игроков нормально. Если пойдёт
  тысячами — переделать `Storage` на SQLite, интерфейс уже под это подходит.
- **Бот лежит = новые игроки не войдут.** Старые с доверенного IP заходят
  спокойно, для остальных есть `/tgauth force`.

## Что можно добавить дальше

- Двухфакторность для админов: подтверждение в Telegram на каждый вход, даже
  с доверенного IP
- Уведомление владельцу, если кто-то жмёт «Не я» — вероятная попытка взлома
- Логин по кнопке в боте вместо кода: `/start CODE` через deep-link `t.me/bot?start=K7F2QX`
  (в боте это уже поддержано, осталось вывести ссылку в игре кликабельной)
- Связка с вашим Bao: общий бот, где авторизация — один из разделов
